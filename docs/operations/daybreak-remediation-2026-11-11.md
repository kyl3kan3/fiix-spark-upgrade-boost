# Daybreak remediation and rollout

The source patch does not change running deployments or close Daybreak findings. Review the per-finding inventory in `docs/daybreak-findings-2026-11-11.json` and rerun the required checks on the exact final commit before release.

Deploy the database migration and compatible frontend/Edge Functions together. Back up the database and validate the migration against a staging copy of the real schema first. PostgreSQL 17 synthetic-tenant and concurrent-session tests pass, but this repository lacks its original base-schema migration; a clean historical reset and Supabase Storage MIME enforcement have not been verified. The restored email-infrastructure migration is copied from its original historical source, not reconstructed. Existing ownerless settings and erased trial history cannot be assigned or reconstructed safely from source alone.

Rotate the previously exposed notification secret. Configure a fresh random `NOTIFY_SHARED_SECRET` in Edge secrets and the matching Vault `notify_shared_secret`; the old public key is explicitly rejected. Configure a separate fresh `MAINTENANCE_JOB_SECRET` and matching Vault `maintenance_job_secret` for self-heal/risk scheduler calls. Never reuse the notification capability for maintenance jobs. Verify both scheduled jobs with synthetic tenant data after deployment. Removing literals from files does not rotate running secrets or erase Git history.

Client email addresses no longer authorize outbound mail. Self-mail uses verified Auth email; invitations use a current administrator's pending unexpired invitation and a fixed server template. Trial notices derive authoritative tenant identity; an optional `TRIAL_OPERATIONS_EMAIL` receives a generic notice without signup PII. Local suppression and prior unsubscribe-token usage are enforced before delivery; the restored unauthenticated unsubscribe endpoint accepts only opaque existing capabilities. Test old unsubscribe links against staging. Email budgets deliberately reserve before delivery and fail closed, so provider failure can consume the retry allowance. Resolution emails contain fixed content and are limited per actor, request and recipient.

Advertising scripts, DataFast forwarding, enhanced conversions, remote badges and automatic Sentry PII collection are removed. Configure `VITE_SENTRY_DSN` only for an authorized monitoring project; without it reporting is off. Error diagnostics retain standard exception types and bundled script positions, not user identity, requests, headers, URLs or error payloads. Source maps are not publicly emitted. Revoke any existing public SEOReceipts statistics publication in that provider account if it was not intended to be public; removing the badge cannot revoke that publication.

Three findings require external evidence: Google OAuth signup anti-abuse must be enforced at Auth/provider creation rather than in the browser; the Search Console verification token must be confirmed as the authorized owner's; and the target Supabase project ownership/migration must be confirmed. The connected Supabase account does not expose the current or previous project. Do not switch backend destinations or replace ownership tokens without that evidence.
